Integrate

Put Tollgate between your agent and PayPal in a few minutes. Your agent asks Tollgate to pay; Tollgate decides; only approved payments reach the PayPal sandbox.

Quick start

Run Tollgate, open the Dashboard and press Run all scenarios to watch six sample agents get allowed, held or blocked.

npm install
npm start
# open http://localhost:3000

With no PayPal keys it runs in simulation mode. To use the real PayPal sandbox, put your sandbox client id and secret in .env (see .env.example). Live PayPal is refused on purpose.

HTTP API

Any agent framework can call one endpoint. Send what the agent wants to buy, what the user asked for, and the text the agent read before deciding.

curl -X POST http://localhost:3000/api/requests \
  -H "content-type: application/json" \
  -d '{
    "agentId": "shopper",
    "action": "order",
    "amount": 24,
    "merchant": "bookstore.example",
    "description": "Birthday book",
    "userIntent": "Buy a birthday book under $30",
    "context": "Product page: a hardcover book, $24."
  }'

For a payout, use "action": "payout" with a "recipient" email instead of a merchant. Payouts always need your approval.

Agent keys

Create an agent on the Agents page to get a key that starts with tg_. Send it as a bearer token. The key decides which agent the request belongs to, so an agent cannot pretend to be another one and spend its budget.

curl -X POST http://localhost:3000/api/requests \
  -H "authorization: Bearer tg_your_key_here" \
  -H "content-type: application/json" \
  -d '{"action":"order","amount":24,"merchant":"bookstore.example","userIntent":"Buy a book"}'

Tollgate stores only a hash of each key. Rotate a key any time and the old one stops working at once. Turn on Require an agent key on the Rules page to refuse anonymous requests.

MCP (Claude and other MCP clients)

Tollgate ships an MCP server, so a Claude agent gets guarded payment tools without any glue code: guarded_create_order, guarded_send_payout, get_payment_status and get_spending_limits. Add this to your MCP client config, using the full path to this folder:

{
  "mcpServers": {
    "tollgate": {
      "command": "node",
      "args": ["/full/path/to/tollgate/src/mcp-server.js"],
      "env": {
        "TOLLGATE_URL": "http://localhost:3000",
        "AGENT_ID": "my-claude-agent",
        "TOLLGATE_API_KEY": "tg_your_key_here"
      }
    }
  }
}

TOLLGATE_API_KEY is optional unless you require agent keys.

Reading the answer

Every call returns a short decision the agent can act on:

{
  "id": "8c1f…",
  "status": "pending",        // executed | pending | blocked | rejected | failed
  "riskScore": 55,
  "reasons": ["Amount is above the $50 auto-approve line."],
  "message": "Waiting for the owner to approve. Do not retry; check this request id later."
}

Poll GET /api/requests/:id to see when a held payment is approved or rejected. Agents only ever see this short answer, never the internal log.

Alerts

Add a webhook URL on the Rules page. When a payment is held or blocked Tollgate posts JSON like this (it has both text and content, so Slack and Discord accept it as is):

{
  "event": "tollgate.held",
  "text": "Tollgate: 75.00 USD order to bookstore.example was held for your approval. …",
  "record": { "id": "…", "status": "pending", "agentId": "shopper", "amount": 75, "riskScore": 0, "reasons": ["…"] }
}

Safety notes

Hard rules always win: a rule violation is blocked even if the AI review likes the request. The AI review can only raise a risk score, never lower it. Text from agents and web pages is always shown as plain text. Set ADMIN_TOKEN before deploying anywhere other than your own computer, or anyone could approve payments.
